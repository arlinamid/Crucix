# Crucix 2.52.1 — URL-összevonás Node 22-n / Merging by URL on Node 22

**Kiadás dátuma / Release Date:** 2026-10-17

---

## 🇭🇺 Magyar

- **A hiba.**
  - A history URL szerinti kulcsa eddig így nézett ki: fajta + NUL karakter + URL. A Node 22 `node:sqlite`-ja a kötött szöveget a NUL-nál levágja, ezért ott minden hírkulcs csak „news” lett.
  - Így ugyanaz a cikk új azonosítóval nem vonódott össze a korábbi rekorddal, hanem duplikátum lett.
  - Node 24-en (és a Node 24-gyel épített helyi exében) nem jelentkezett.
  - A CI Node 22-es tesztjei kimutatták (két teszt), ezért a v2.52.0 npm-publikálása elmaradt. A v2.52.0 Release binárisai Node 22-vel épültek, így bennük a hiba megvan.
- **A javítás.**
  - Az elválasztó szóköz lett (URL-ben nincs nyers szóköz).
  - A meglévő adatbázisok régi kulcsait a háttér-karbantartás (a munkafolyamatban futó tömörítés) írja át, 2000-es adagokban. Az élő adat másolatán ez 65 593 kulcs 17 s alatt; a megnyitás 53 ms marad.
  - A Node 24 által írt kulcsokból SQL vágja ki az URL-t BLOB-ként, mert a SQLite szövegfüggvényei is megállnak a NUL-nál. A Node 22 által csonkolt kulcsokat a rekordból számolja újra.
  - Amíg ez nem futott le, egy a frissítés előtt látott és utána újra felbukkanó cikk kétszer kerülhet a historyba.
- Új teszt: egyik kulcs sem tartalmaz NUL-t, és mindkét régi formátum adagonként átíródik.

## 🇬🇧 English

- **The bug.**
  - The history's URL key was kind + NUL + URL. Node 22's `node:sqlite` cuts a bound string at a NUL, so there every news key became "news".
  - The same article under a new id was then not merged into its earlier record but kept twice.
  - Node 24 (and the local executable built with it) was not affected.
  - CI's Node 22 tests caught it (two tests), so v2.52.0 was not published to npm. The v2.52.0 Release binaries were built with Node 22 and carry the bug.
- **The fix.**
  - The separator is a space (a URL has no raw space).
  - The keys of an existing database are rewritten by the background maintenance (the compaction, in the worker), 2,000 at a time. On a copy of the live data: 65,593 keys in 17 s; opening stays at 53 ms.
  - Keys written by Node 24 have their URL cut out as a BLOB in SQL (SQLite's text functions stop at the NUL too). Keys Node 22 cut to the kind are computed again from their record.
  - Until that has run, an article seen before the upgrade and again after it may be kept twice.
- New test: no key holds a NUL, and both old formats are rewritten in batches.
