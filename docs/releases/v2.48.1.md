# Crucix 2.48.1 — Aszinkron history-mentés és hibás források a health-ben / Asynchronous history backup and failing sources in health

**Kiadás dátuma / Release Date:** 2026-10-15

---

## 🇭🇺 Magyar

A 2026-10-15 13:30-as automatikus élő ellenőrzés ([docs/audit/live-check-2026-10-15.md](../audit/live-check-2026-10-15.md)) nyomán.

- **Aszinkron napi mentés.**
  - A `history.db.bak` eddig `VACUUM INTO`-val készült. Ez szinkron művelet, 65 MB-nál kb. 1–2 s-ig blokkolta a szervert.
  - Most a `node:sqlite` online `backup()`-ja készíti: 256 lapot másol egy lépésben, a lapok között a szerver kiszolgálja a kéréseket.
- **Mentés közvetlenül egy import után.** Az élő ellenőrzés szerint a napi mentés 03:33-kor készült, az import 03:35-kor végzett, így egyik mentés sem tartalmazta a visszanyert ~13 500 rekordot. Mostantól egy import után a karbantartás soron kívüli mentést készít.
- **Hibás források a health-ben.** Az `/api/health` válaszban új mező a `failingSources` és a `staleSources` (forrásnevek).
- **Napi bontás az első észlelés szerint.** A history-lekérdezés statisztikájában új mező a `firstSeenDays`.
  - A meglévő `days` idővonal a legutolsó észlelés napja szerint számol. Egy újra látott történet így „átvándorol” a mai napra, és a régebbi napok darabszáma lassan csökken. Ez nem adatvesztés.
  - A `firstSeenDays` egy rekordot mindig az első észlelése napjánál számol.

## 🇬🇧 English

Following the automatic live check of 2026-10-15 13:30 ([docs/audit/live-check-2026-10-15.md](../audit/live-check-2026-10-15.md), Hungarian).

- **Asynchronous daily backup.**
  - `history.db.bak` used to be made with `VACUUM INTO`. That is a synchronous operation, and at 65 MB it held the server for about 1–2 s.
  - It is now made with the online `backup()` of `node:sqlite`: 256 pages per step, and the server answers requests between steps.
- **A backup right after an import.** The live check found that the daily backup ran at 03:33 and the import finished at 03:35, so no backup held the ~13,500 recovered records. From now on, the maintenance makes an extra backup right after an import.
- **Failing sources in health.** New `/api/health` fields: `failingSources` and `staleSources` (source names).
- **Daily counts by first sighting.** New field in the history query statistics: `firstSeenDays`.
  - The existing `days` timeline counts a record on the day of its latest sighting. A story seen again therefore "moves" to today, and older days slowly shrink. This is not data loss.
  - `firstSeenDays` always counts a record on the day it was first seen.
